# Phishing URL Detection — Model + API

Reconstructed from *"A Dynamic Phishing URL Detection System Integrating
Advanced Machine Learning and Crowdsourced Threat Intelligence"*
(Aldhuwayhi & Alromih, 2026), trained on the
[PhiUSIIL Phishing URL Dataset](https://www.kaggle.com/datasets/ndarvind/phiusiil-phishing-url-dataset).

## Project layout

```
phishing_api/
├── requirements.txt
├── .env.example
├── train.py                  # trains the model, writes everything into artifacts/
├── core/
│   ├── config.py              # single source of truth for paths, label mapping, columns
│   ├── preprocessing.py       # cleaning, feature selection, SMOTE, tokenization
│   ├── model_arch.py          # build_model() — the hybrid LSTM+Attention/Dense network
│   └── inference.py           # PredictionService: loads artifacts, serves predictions
├── api/
│   ├── main.py                 # FastAPI app + routes
│   └── schemas.py              # Pydantic request/response models
├── artifacts/                  # generated by train.py — model, tokenizer, scaler, etc.
└── data/                       # put the PhiUSIIL CSV here
```

## Setup

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# get the dataset
pip install kaggle
kaggle datasets download -d ndarvind/phiusiil-phishing-url-dataset -p ./data --unzip
cp .env.example .env            # then edit ADMIN_TOKEN before deploying anywhere real
```

## Train

```bash
python train.py
```

Writes to `artifacts/`:
- `hybrid_model.keras`, `tokenizer.pkl`, `num_scaler.pkl`
- `selected_features.pkl`, `tld_categories.pkl`, `onehot_columns.pkl`
- `learning_curves.png`, `evaluation_plots.png` (confusion matrix + ROC)

The loader **asserts** the label mapping (`1 = legitimate, 0 = phishing`,
per the dataset docs and the paper's reported class counts) against your
actual CSV and fails loudly on mismatch — read that assertion the first
time you run it.

## Run the API

```bash
uvicorn api.main:app --reload --port 8000
```

Recommended (quiet TF logs & CPU-only) run wrapper:

```bash
./run_server.sh
# stderr is written to `uvicorn.err.log` to keep the console clean.
```

## API contract (what the frontend needs)

### `GET /health`
```json
{"status": "ok", "model_loaded": true, "num_features_expected": 34}
```

### `GET /schema/features`
Call this first (e.g. on page load) — it tells the frontend exactly what
fields to collect and how to render/validate them, so the form doesn't
have to hardcode the feature list:
```json
{
  "fields": [
    {"name": "URL", "type": "string", "required": true},
    {"name": "Title", "type": "string", "required": false},
    {"name": "IsHTTPS", "type": "boolean"},
    {"name": "TLD", "type": "enum", "options": ["com", "org", "net", "other_tld", "..."]},
    {"name": "URLSimilarityIndex", "type": "float"}
  ]
}
```

### `POST /analyze` or `POST /predict-url` (combined flow)
Request:
```json
{
  "url": "https://example-bank-login.com/verify",
  "title": "Verify your account",
  "features": {
    "IsHTTPS": true,
    "TLD": "com",
    "URLSimilarityIndex": 42.5,
    "NoOfSubDomain": 1,
    "...": "...rest of the fields from /schema/features"
  }
}
```
Response:
```json
{
  "url": "https://example-bank-login.com/verify",
  "extraction": {
    "url": "https://example-bank-login.com/verify",
    "title": "Verify your account",
    "features": {
      "IsHTTPS": true,
      "TLD": "com",
      "URLSimilarityIndex": 42.5,
      "NoOfSubDomain": 1
    },
    "warnings": []
  },
  "prediction": {
    "probability_legitimate": 0.03,
    "probability_phishing": 0.97,
    "predicted_label": 0,
    "predicted_class": "Phishing",
    "threshold": 0.5
  }
}
```

### `POST /report` — crowdsourcing input (paper Section IV.A.3)
Same body as `/predict`, plus an optional `reporter_note`. Scores the URL
immediately (for user feedback) **and** queues it for admin verification.
```json
{"report_id": 17, "status": "queued_for_review", "model_prediction": {...}}
```

### Admin endpoints (require `X-Admin-Token` header)
- `GET /admin/reports/pending` — list unverified reports
- `POST /admin/reports/{id}/verify` — body `{"true_label": 0}`, appends
  the verified row to `artifacts/retrain_dataset.csv`
- `POST /admin/retrain` — reruns `train.py` as a blocking subprocess
  (**illustrative only** — see caveats below)

## Known limitations / things to verify yourself

1. **Feature extraction from a raw URL isn't automated end-to-end.**
   `/predict` and `/report` expect you to already have the ~30
   PhiUSIIL-style feature values for a URL (`URLSimilarityIndex`,
   `NoOfSubDomain`, `HasFavicon`, etc.). About a third of these
   (favicon checks, iframe/popup counts, redirect resolution, form
   field detection...) require fetching and parsing the live page —
   that's a separate scraping component (requests + BeautifulSoup) not
   included here. If you need "just paste a URL," build that
   extractor and call it before hitting `/predict`.
2. **`/admin/retrain` is a manual, blocking trigger**, not production
   automation — no job queue, no hot model reload (restart the process
   after retraining), and it doesn't merge `retrain_dataset.csv` back
   into the source dataset for you.
3. **Admin auth is a placeholder** (single static token via header).
   Replace with real auth before exposing these endpoints publicly.
4. **Label mapping**: double-check the assertion output when you first
   run `train.py` — get this wrong and every prediction is inverted.
5. Hyperparameters not stated in the source paper (tokenizer scheme,
   batch size, learning rate, vocab size, max URL length) are set to
   reasonable defaults in `core/config.py`, not values taken from the
   paper. Don't expect the paper's reported 99.8% accuracy without
   your own tuning pass.
